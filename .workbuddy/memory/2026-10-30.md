### 2. GLTF 模型查看
- `GltfViewer.vue` `loadFromBytes()`：修复 GLB 字节转 ArrayBuffer 的方式。原来直接用 `bytes.buffer.slice(byteOffset,...)`，在 Tauri readFile 返回的 Uint8Array 经 IPC 传输后 buffer 可能分离/偏移错位导致解析失败。改为先 `bytes.slice()` 复制出连续 buffer 再 slice。
- **Draco 支持（最终方案，已实测通过）**：
  - 根因：three 官方 `DRACOLoader` 依赖 `fetch` 加载解码器 + `new Worker(blob:)` 解码；Tauri CSP 缺 `worker-src blob:` 时 Worker 被拦，`parse` 既不 resolve 也不 reject → 页面永远停在"正在加载模型"。
  - 方案：新建 `src/utils/dracoSync.js`，**主线程同步解码**——wrapper 源码（`draco_wrapper_raw.js`，字符串内联）+ wasm（`draco_wasm_base64.js`，base64 内联）经 `new Function(module,exports,globalThis,src)` 执行拿到 `DracoDecoderModule` 工厂，用 `{ wasmBinary }` 初始化，避开 fetch/XHR/Worker。
  - 对外暴露 `createSyncDracoLoader()`，接口兼容 DRACOLoader（`preload` / `decodeDracoFile`）。
  - 实测：Node + 浏览器均验证；LittlestTokyo.glb 的 71 个 draco primitive 全部解码成功；Node 单次解码 4ms。
  - 另在 `tauri.conf.json` CSP 补 `worker-src: ["'self'","blob:"]` 作为兜底。
  - `loadFromBytes` 加 60s 超时，避免任何情况下永久 loading。

### 7. 图片压缩：导出格式不跟随选择（选 PNG 却导出 WEBP）
- 根因：`ensureSmaller()` 在"结果比原图大"时偷偷把输出换成 WEBP 质量 0.9 并返回，扩展名跟着 `out.format` 走，于是选 PNG 也会得到 .webp。
- 修复（`src/views/pictures/ImgCompress.vue`）：输出格式严格等于用户选择，降体积改为"同格式内降级"：
  1) 目标 PNG（无损）→ 新增 `quantizePng()`（`src/utils/image.js`）做减色重编码：中位切分调色板 + 无抖动映射 + canvas 重编 PNG，按 256/128/64 色尝试，只有比原图小 5% 以上才采用（避免为一点收益丢颜色）；
  2) 目标 JPG/WEBP（有损）→ 逐级降质量 0.85/0.7/0.55/0.4/0.25，格式不变；
  3) 都降不下来 → 原图格式 == 目标格式时直接输出原文件（标"已是最优"）；格式不同则按所选格式输出，宁可体积增大也不改格式。
- UI：压缩后列新增输出格式标签（PNG/WEBP…），结果标签加 tooltip 说明（原文件最优 / 减色到 N 色）；PNG + 有损原图时提示条出现"改用 WEBP"一键切换；顺带把压缩强度说明文字换行，避免和滑块"自定义"刻度重叠。
- 复用：`quantizePng` 复用了 `utils/gif.js` 的 `medianCutPalette` / `mapFrameToIndices`（dither=false），image.js 顶部 import gif.js（gif.js 无反向依赖，不成环）。
- 实测（CDP 注入真实文件后点击压缩）：solid.png 585B → 585 B | PNG | 已是最优；noisy.png 863KB → 375KB | PNG | 减小 55.6%；壁纸 jpg 选 PNG → 7.48MB | PNG | 增大 389%（有提示与一键改 WEBP），改 WEBP 后 178KB | -88.6%。

### 17. 图片预览：缩放 + 拖动
- 需求「图片预览弹窗要让图片可以放大缩小、移动位置」，都在 `src/views/pictures/ImgCompress.vue` 的预览弹窗里。
- **状态设计**：`zoom = reactive({ scale, tx, ty, dragging, pointerId, startX, startY, fromX, fromY })`。`scale` 是**相对「适应窗口」的倍数**（1 = 刚刚放满），`tx/ty` 是相对居中的像素位移。图片仍是 flex 居中 + `transform: translate3d(tx,ty,0) scale(s)`，不参与布局，所以 `offsetWidth` 始终是适应尺寸。
- **百分比按原始像素算**：`fitBox = { w, h, naturalW, naturalH }` 在 `<img @load>` 里量（`offsetWidth` 不受 transform 影响），`zoomPercent = round(fitBox.w * scale / naturalW * 100)`。这样「100%」就是 1 图px = 1 屏幕px，和常见看图软件一致（900×600 的图在 1364×599 的舞台里适应态显示 97%）。
- **锚点缩放公式**（图片 flex 居中，所以锚点用「相对容器中心的偏移」a 表达）：`t' = a - ((a - t) / s) * s'`。实测缩放到 3.032 倍时锚点下的图片像素漂移 0.09px / 0.31px。
- **交互**：滚轮（`deltaMode` 归一化，`factor = exp(-deltaY * 0.0016)`，一格约 ±15%）、`+`/`-`/`0` 键、双击（放大时复位、适应时跳到 1:1 并对准鼠标点）、工具条 `− / 百分比 / + / 1:1 / 适应`（浮在图片区底部中间，`position:absolute` + 药丸样式，`@pointerdown.stop` 防止连带拖动）。
- **拖动**：Pointer Events + `setPointerCapture`，只在 `scale > 1.001` 时启用（`canPan`），光标 `grab`/`grabbing`；`clampPan()` 把 `tx/ty` 限制在 `(显示尺寸 - 容器内宽) / 2` 内，放大后最多拖到图片边缘贴住窗口，不会把整张图拖丢。
- **复位时机**：`watch([preview.open, preview.id, preview.side])` → `fitZoom()`；窗口 `resize` → 重新量尺寸并 `clampPan()`。
- **样式**：`.preview-stage` 加 `position:relative; overflow:hidden; user-select:none; touch-action:none`，`img { will-change: transform; -webkit-user-drag: none }`；深色主题下 `.zoom-bar` 换深底 + 白边。
- **探针** `window.__imgCompressTest.zoom`：`state / to / by / actual / fit / wheel(deltaY,x,y) / pan(dx,dy) / imgBox()`。
- **实测**（1424×749 视口，900×600 图）：适应态 `shown 875×583`、97%、`canPan=false`；1:1 → `scale 1.029`、`shown 899×600`、100%；`to(3)` → `2624×1749`；真实 PointerEvent 拖 −260/−140 → `tx/ty` 一致；真实 WheelEvent 滚动后 `window.scrollY` 未变（`@wheel.prevent` 生效）；滚轮连缩 6 次到 0.363 → `tx/ty` 归零居中；双击在放大态回适应、在适应态跳 1:1；`to(4)` 后拖到极限 `imgLeft 39`（舞台 30 + padding 8）、`imgTop 100`（舞台 92 + 8），正好贴边不越界；换图 / 切原图-压缩后 / 上限下限（0.2~8）钳制均正确。
- 回归：`npx vite build` 通过；全站 44 页 `check-pages.mjs` 无报错；适应态与 3.89 倍放大态两张截图目视检查通过。

### 18. 图片压缩预览改用 Viewer.js（去掉自研弹窗）
- 需求「不要把预览图片放在弹窗里，直接就只显示图片，直接用第三方图片预览库」。装了 **`viewerjs@1.15.2`**（vanilla，不绑框架；`v-viewer` 之类要按 Vue 版本挑包，反而更麻烦），并且删掉了上一轮那一整套自研弹窗 + 缩放/拖动。
- **装包坑**：`npm i` 在这个项目里直接崩（`TypeError: Cannot read properties of null (reading 'matches')`，arborist 读不懂 `node_modules/.pnpm` 的布局）。项目本来就是 pnpm 管理（有 `pnpm-lock.yaml`），改用 `pnpm add viewerjs` 正常。
- **图片序列怎么喂**：模板里放一个 `.viewer-host`，`v-for` 渲染当前这一组图片（原图组 = 全部 `item.url`；压缩后组 = 有 `out` 且 `previewUrl` 的），容器 `position: fixed; left: -10000px; width/height: 1px; overflow: hidden; opacity: 0; pointer-events: none`——**不能 `display:none`**，库要靠这些 `<img>` 建列表，但也不能占页面布局。
- **打开流程** `openPreview(item, side)`：先切 `viewerSide` → `await nextTick()`（等 v-for 把新一组图挂上）→ `ensureViewer()` 懒创建 → `instance.update()` 重新收图 → 按 `${id}-src|out` 找到下标 → `instance.view(index)`。
- **两个库的坑**：
  1. **关闭动画期间 `view()` 会被静默忽略**（`if (this.hiding) return this`），用户关掉后马上点另一张会「点了没反应」。加了 `waitViewerIdle()`：`hiding` 期间每 30ms 轮询一次（上限 1s）再 `update + view`。
  2. **`exit()` 对 `inline: false` 直接 return**（它只管 inline 模式的全屏切换），关弹窗要用 `hide()`。
  3. `toolbar` 传自定义对象时是**整体替换**而不是合并（`forEach(custom ? options.toolbar : BUTTONS)`），所以要把想要的按钮全写出来；`play: false` 去掉幻灯片。
  4. 键盘走 `event.keyCode`（`keydown` 里 `if (!this.fulled) return`，`shown()` 时才置 `fulled=true`），探针里造 `KeyboardEvent` **必须带 `keyCode`**，只给 `key` 测不出来。
- **配置**：`inline: false`（全屏遮罩）、`title: image => image.alt`（只显示文件名）、`navbar: false`、`toolbar` 只留 zoom/in/out、1:1、reset、prev、next、左右旋转、水平/垂直翻转；`movable/zoomable/scalable/rotatable: true`，`zoomRatio 0.12`、`min 0.1`、`max 12`。
- **删掉的东西**：`preview` reactive、`previewSrc/Meta/Foot/Index`、整套 `zoom/fitBox/applyZoom/clampPan/pan` 代码、`a-modal`、那个非 scoped 的 `.img-compress-preview` 样式块（含深色主题覆盖）；`reactive/watch/onMounted` 变成无用 import 也一并清掉，只 `onUnmounted` 里 `viewer?.destroy()`。
- **探针**：`window.__imgCompressTest` 新增 `viewerState()/previewState()`（含 `active/index/length/title/ratio/shownSrc/sources/domImages/flags{hiding,showing,isShown,viewed,ready}`）、`viewer.{zoomin,zoomout,to,rotate,next,prev,close,dom}`；`open()` 改成 async。
- **实测**：真实点「原图」缩略图 → side=origin、index=0、title `test-1.png`、canvas img 900×600（1:1）；点「看效果」→ side=compressed、index=1、title `test-2.png（压缩后）`；工具栏 10 个按钮不含 play；`←`/`→` 切换、`Esc` 关闭（`viewed=false`、容器 `display:none` + `viewer-hide`）；关闭 80ms 后立刻重开也正常；像素采样确认遮罩生效（页面白底采样值 123~127 ≈ 50% 黑叠加）。
